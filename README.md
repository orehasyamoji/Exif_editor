# Film EXIF

フィルムをデジタルデュープしたJPEGの機材・露出情報を、撮影時の情報へ一括編集する日本語のWebアプリです。写真の編集・ZIP作成は端末内で完結します。外部API、アクセス解析、外部フォント、CDNへの実行時依存はありません。

## 起動と開発

Node.js 24 LTS / npm を使用します（`.nvmrc`）。バックエンド、DB、APIキーは不要です。

```sh
npm ci
npm run dev
```

開発サーバーは5173番ポートで動きます。PWAのキャッシュは開発モードでは登録しません。本番相当の確認には以下を使用してください。

```sh
npm test
npm run build
npm run preview -- --port 4173
```

`dist/` が公開用成果物です。HTTPSで配信してください（PCのlocalhostもService Workerを利用できます）。`file://` でHTMLを直接開く方法や、iPadからLANのHTTPサーバーへアクセスする方法ではPWAを利用できません。

## 使い方

1. 「写真を選ぶ」で写真を複数選びます。名前の自然順（例：2→10）で並びます。選び直すと一覧と個別露出を入れ替えます。
2. メーカー・カメラ・レンズを入力、または機材プリセットを選びます。機材欄の空欄は対応タグを削除します。
3. ロール共通のISOを指定します。
4. 露出の未設定／一括入力／個別入力を選びます。空欄はタグ削除です。F値とシャッターは独立して未設定にできます。候補にない数値は「任意の値を入力…」から入力します。シャッターは `1/125` または `0.008` のように指定します。
5. 「書き出す」を押し、成功・失敗・警告を確認します。
6. 「ZIPを保存」を押します。ZIPには成功したJPEGのみが入ります。失敗したファイルは再選択して再処理できます。

iPadでは左に設定、右に写真一覧、下に書き出し操作を表示します。詳細な注意事項は右上の「ヘルプ」から確認できます。「プリセットを保存」を開くと保存名・新規保存・上書き保存を操作できます。狭い画面では1列に並びます。

元ファイルは上書きしません。同名・大文字小文字のみ異なる名前には ` (2)` などを付けます。ZIP内のファイル名はUTF-8です。パス区切り等は安全な文字へ置換します。元の撮影日時は保持しますが、ZIPエントリー自体の日付は固定（1980年）です。

プリセットは `localStorage` に機材名とプリセット名のみを保存します。ISO・露出・写真は保存しません。「新規保存」「上書き保存」「削除」に対応します。ブラウザ・プロファイル・サイトのURLごとに別の保存領域です。Safariとホーム画面版で保存領域が分かれる場合があります。サイトデータ消去・プライベートブラウズ等では永続性を保証できません。

## iPad Safariでの確認

対象の目安は iPadOS 17以降のSafariです。実機の動作確認はまだ実施していません。

1. HTTPSで公開したアプリをSafariで開き、「オフライン準備完了」を待ちます。
2. 共有メニュー →「ホーム画面に追加」を選びます。ホーム画面版も一度オンラインで開いて準備完了を確認します。
3. ファイルアプリ内にあるJPEGを24〜36枚用意します。iCloudの写真は事前に端末へダウンロードしてください。
4. プリセットの新規保存・呼び出し・上書き・削除を確認します。
5. 未設定、一括入力（片方だけ未設定も含む）、個別入力でZIPを保存します。Safariのダウンロード／ファイルアプリからZIPを展開し、実際に使う写真管理ソフトで機材・ISO・露出・日時・向きを確認します。
6. 機内モードにしてホーム画面版を閉じ、再度開きます。プリセット呼び出しからJPEG選択・ZIP保存まで実施します。
7. 正常なJPEGと壊れたJPEGを混ぜ、失敗した名前と成功枚数が表示されることを確認します。
8. 大きい実写JPEGでは少ない枚数から確認します。処理中はアプリを前面に保ってください。

キャッシュが完了したアプリ本体はオフラインで動作します。Safariがストレージを自動削除した場合は再接続が必要です。アプリの新しい版はバックグラウンドで取得します。処理完了後、このサイトのタブ／ホーム画面版をすべて閉じて開き直すと更新されます。

## 技術とEXIFの方針

- **Vanilla JavaScript ES Modules + Vite**：静的アプリ。実行時の外部ライブラリは不要です。
- **`src/exif.js`**：JPEGマーカーとTIFFのIFDを読み、更新用のIFDをAPP1内の末尾に追加してルート参照を切り替えます。元TIFFデータを移動せず、MakerNote等の元の相対オフセットを維持します。リトル／ビッグエンディアン両対応です。
- **`src/zip.js`**：ZIP STORE形式。再圧縮しないJPEGをCRC-32付きで格納します。CRCは1 MiBずつ計算し、Blobのパーツを利用して巨大な連結配列を避けます。
- **`src/presets.js`**：バージョン付きのブラウザ保存。
- **`src/main.js` / `src/style.css` / `index.html`**：タッチ操作向けUI、入力検証、逐次処理、ファイルごとの結果。
- **`vite.config.js` / `public/`**：ビルド済みJS/CSS・HTML・アイコン等をキャッシュするService WorkerとPWA定義。

画像をCanvasへ描画せず、再エンコードもしません。既存EXIFがあればそのAPP1だけを交換し、なければAPP0の後（APP0がなければSOIの後）に追加します。他のJPEGセグメントとSOS以降の圧縮画像データは元のバイト列を使用します。

| 項目 | 処理 |
| --- | --- |
| メーカー・カメラ・レンズ | IFD0 `Make`・`Model`、ExifIFD `LensModel` を更新。空欄は削除 |
| ISO | `ISOSpeedRatings`、`SensitivityType=3`、`ISOSpeed` を更新。古いSOS/REI/ISO緯度値を削除 |
| F値 | `FNumber` と `ApertureValue=2 log₂(F)` を更新／削除 |
| シャッター | `ExposureTime` と `ShutterSpeedValue=−log₂(t)` を更新／削除 |
| 撮影日時・GPS・サイズ・向き | 元のIFDエントリーと値を維持 |
| ICC・XMP・IPTC・コメント等 | EXIF以外のセグメントをバイト単位で維持 |

複写機材の `LensSpecification`・`LensMake`・レンズ／ボディのシリアル番号・`MaxApertureValue` は新しい機材と矛盾するため削除し、該当時は警告します。焦点距離・露出補正・測光・フラッシュ等、指定外のタグは保持し、残存時は警告します。

## 制約と設計上の判断

- **非対象情報の保持を優先**：MakerNote、XMP、IPTC、埋め込みサムネイル内の機材・露出は更新しません。該当ファイルでは警告を表示します。写真管理ソフトによってはXMP側の古い値を優先するため、必要なら別ツールで整合させてください。MakerNoteのメーカー独自解釈まで保証するものではありません。
- **プライバシー除去用途ではありません**：元のIFDや文字列は未参照データとしてEXIF内に残ります。一般的なEXIFリーダーには更新後のタグが見えますが、バイナリ解析では元の値を回収できることがあります。GPSも保持します。
- **安全に処理できないファイルは失敗として除外**：複数EXIF、MPF/MPO、破損したIFD、未知のTIFF型、JPEG APP1の約64KB上限超過は変更せず失敗にします。再編集を繰り返すと追記で上限に近づくため、元JPEGから編集してください。
- **ISOの範囲**：任意の正の整数をEXIFの32ビット上限 `4294967295` まで受け付けます。65535以上は16ビットタグを65535にし、32ビットの `ISOSpeed` に実値を記録します。古い写真管理ソフトでは拡張ISOを表示できない場合があります。
- **文字コード**：ASCII文字列タグに日本語等を指定した場合はUTF-8で格納し、互換性警告を出します。ASCII専用リーダーでは文字化けします。互換性を優先するなら英数字を使用してください。
- **F1未満**：`FNumber` は記録しますが、負のAPEX値を表せないunsigned RATIONAL型の `ApertureValue` は削除し、警告します。
- **露出の入力範囲**：正の数／分数で `0.000001〜1000000`。EXIFのRATIONAL/SRATIONAL形式で記録します。
- **メモリ**：1枚ずつ読み込み、プレビュー画像を生成しません。合計256 MiB・200枚の上限があります。出力BlobとZIPはメモリ上に残るため完全なストリーミングではありません。iPadの空きメモリ次第でこれ以下でもタブが終了する可能性があります。大きいJPEGはロールを分割してください。新しい選択・設定変更時は古いZIPのURLを解放します。写真と個別入力は再起動時に保持しません。

## 自動テスト

```sh
npm test
# ブラウザを未導入の場合（一度だけ）
npx playwright install --with-deps chromium webkit
npm run test:e2e
# OS標準Chromiumのみでも確認可能
npm run test:e2e -- --project=chromium-ipad
```

`CHROMIUM_PATH` でChromiumの実行パスを指定できます。`/usr/bin/chromium` があればそれを使い、なければPlaywrightのバイナリを使用します。WebKitはPlaywright版を使用します。

- Nodeテスト **11件成功**：独立した `exif-reader` で機材・ISO・APEX・日時・GPS・向き・サイズ・MakerNoteを再読。II/MM両形式、独立した未設定処理、拡張ISO、壊れた入力、容量上限を検証。非EXIF全バイト（圧縮画像・ICC・XMP等）が一致することを検証。36枚ZIP・独立CRC検証・重複名・プリセット保存も含みます。
- ChromiumのiPad相当E2E **9件成功**：36枚＋破損1枚、個別入力と全未設定、プリセットCRUD、通信をオフにした再読み込み→編集→ZIPダウンロード、入力エラー、保存領域の容量エラー、小画面幅を確認。ヘルプの開閉とフォーカス復帰、オフライン準備エラーの詳細表示、古いHTMLが配信される更新時の整合性と旧アセットのオフライン保持、iPad縦横の2ペイン配置・書き出し表示・44px以上の操作領域、写真の選択解除も検証します。GitHub Pages相当の `/Exif_editor/` 配信でもオフライン再読み込み・編集・ZIP保存のスモーク確認に成功しました。
- WebKit E2Eはこのクラウド環境では **未実行**：ブラウザ配布ドメインへのアクセスが403で拒否されたためです。実機Safariも未検証です。合成した小さいJPEGによる自動検証は実写・端末でのメモリ検証の代わりにはなりません。
- `npm run build` **成功**。

`tests/fixtures/base.jpg` は単色画像を生成したテスト用JPEGです。テスト用TIFF/GPS/ICC等は `tests/fixture.js` が組み立てます。テスト専用の `exif-reader` やPlaywrightは公開アプリには含めません。

## GitHub Pages公開手順

コードを `main` に反映した後は、次の操作だけで公開できます。プログラミングや端末のコマンド操作は不要です。

1. [リポジトリのPages設定](https://github.com/orehasyamoji/Exif_editor/settings/pages) を開きます。
2. **Build and deployment → Source** で **GitHub Actions** を選択します。
3. [公開用のActions画面](https://github.com/orehasyamoji/Exif_editor/actions/workflows/pages.yml) を開きます。
4. **Run workflow** を押し、Branch が **main** であることを確認して、緑色の **Run workflow** を押します。
5. 数分待ち、処理が緑のチェックになったら公開完了です。表示された公開URLをiPadのSafariで開きます。通常の公開先は https://orehasyamoji.github.io/Exif_editor/ です。
6. 「オフライン準備完了」を待ち、Safariの共有メニューから「ホーム画面に追加」してください。

公開操作に失敗した場合はActions画面の赤い項目を開いてエラーを確認してください。公開前のPages設定ではURLが表示されない場合があります。`/Exif_editor/` のようなサブパスでも動くよう、ビルドは相対URLを使います。

Pagesのワークフローは手動実行のみです。`main` へpushしただけでは公開されません。PRには `Checks` が走り、NodeテストとChromium/WebKitのE2Eを実行する設定です。GitHub Actionsでの実行自体はまだ確認していません。

他の静的ホスティングでも `dist/` をHTTPSで配信すれば利用できます。`index.html` と `sw.js` は長期キャッシュせず、ハッシュ付き `assets/` のみを長期キャッシュする設定を推奨します。

更新時はService Workerにビルド済みHTMLを含め、同じ版のJS/CSSと組み合わせて保存します。直近の旧版キャッシュも2世代残し、Safariに残る古い文書のアセット欠落を防ぎます。修正前に表示が崩れた場合は、最新版を公開した後、まずSafariのプライベートタブで表示を確認できます。プライベートタブのプリセット保存領域は通常タブとは別です。
